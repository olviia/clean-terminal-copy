  Design idea: don't override Ctrl+C, listen to it

  Instead of taking over Ctrl+C, we let Rider handle it exactly as
  now: copy when text is selected, interrupt when nothing is. Rider
  announces every action it runs, and our plugin listens for that
  announcement. When the action was a terminal copy, we clean the
  clipboard right after. This removes the Ctrl+C risk completely,
  because we never touch the shortcut. This is the Observer pattern:
  we react to an event without changing the code that raises it.

  CRC cards

  IndentStripper (core)
  - Responsibility: knows the rules for turning raw terminal text
    into clean text.
  - Collaborators: none. It's pure text in, text out, with no Rider
    dependency, so it's easy to test and reusable anywhere.

  TerminalCopyListener (adapter)
  - Responsibility: knows which actions count as a terminal copy, and
    decides when to clean.
  - Collaborators: IndentStripper, and Rider's clipboard
    (CopyPasteManager).

  plugin.xml (wiring)
  - Responsibility: registers the listener with Rider.
  - Collaborators: none.

  It's the same hexagonal shape as before: a pure core, plus a thin
  adapter for each outside system.
